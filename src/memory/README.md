# 📘 Java Basic - 자바 메모리 구조와 static

이번 학습에서는 **자바 메모리 구조(메서드 영역 / 스택 영역 / 힙 영역)** 와  
`static` 키워드의 개념과 동작 원리를 배웠다.

---

##  이번에 학습한 핵심 내용

###  자바 메모리 구조 이해

자바의 메모리 구조는 크게 3가지 영역으로 나뉜다.

- **메서드 영역 (Method Area)**
- **스택 영역 (Stack Area)**
- **힙 영역 (Heap Area)**

각 영역의 역할은 다음과 같다.

---

###  메서드 영역

- 클래스 정보(바이트코드, 필드, 메서드 코드 등)를 저장한다.
- `static` 변수와 `static` 메서드가 보관된다.
- 프로그램 전체에서 공유되는 영역이다.
- JVM이 클래스 로딩 시 생성되고, JVM 종료 시까지 유지된다.

-> 클래스 단위의 공용 공간이라고 이해했다.

---

###  스택 영역

- 메서드 호출 시 **스택 프레임**이 생성된다.
- 지역 변수(매개변수 포함)가 저장된다.
- 메서드가 종료되면 스택 프레임이 제거된다.

스택은 **LIFO(후입선출)** 구조로 동작한다.

즉,
- 메서드를 호출하면 쌓이고
- 메서드가 끝나면 제거된다.

-> 실행 흐름과 지역 변수를 관리하는 공간이다.

---

###  힙 영역

- 객체(인스턴스)와 배열이 생성되는 공간이다.
- `new` 키워드를 사용하면 힙 영역에 객체가 만들어진다.
- 더 이상 참조되지 않는 객체는 GC(가비지 컬렉션)에 의해 제거된다.

-> 실제 데이터(객체)가 존재하는 공간이다.

---

###  스택과 힙의 관계 이해

객체를 생성하면

```java
Data data = new Data(10);
```

- `new Data(10)` → 힙에 객체 생성
- `data` 변수 → 스택에 생성
- 스택 변수에는 객체의 **참조값(주소값)** 이 저장된다.

즉,
- 객체는 힙
- 참조값은 스택

이라는 구조를 이해했다.

---

###  참조가 사라지면 어떻게 될까?

- 메서드가 종료되면 스택 프레임이 제거된다.
- 스택에 있던 참조값도 함께 제거된다.
- 힙 객체를 참조하는 곳이 없으면 GC 대상이 된다.

-> 자바는 자동으로 메모리를 관리한다는 점을 이해했다.

---

###  static 변수의 필요성

인스턴스 변수는 객체마다 각각 존재한다.

```java
public int count;
```

이 경우 객체를 여러 개 생성하면  
각 객체마다 count가 따로 존재한다.

→ 전체 객체 수를 세기에는 적합하지 않다.

---

###  static 변수 도입

```java
public static int count;
```

`static` 이 붙으면:

- 클래스에 단 하나만 존재한다.
- 메서드 영역에서 관리된다.
- 모든 인스턴스가 공유한다.

접근 방법:

```java
Data3.count;
```

-> 클래스명 + 변수명으로 접근하는 것이 권장된다.

---

###  변수의 종류 정리

- **지역 변수**  
  -> 스택 영역  
  -> 메서드 종료 시 제거  
  -> 생명주기 짧음

- **인스턴스 변수**  
  -> 힙 영역  
  -> 객체 생성 시 생성  
  -> GC 전까지 유지

- **클래스 변수(static 변수)**  
  -> 메서드 영역  
  -> JVM 로딩 시 생성  
  -> JVM 종료 시 제거  
  -> 가장 긴 생명주기

`static` 이 정적이라고 불리는 이유는  
프로그램 시작부터 종료까지 유지되기 때문이다.

---

###  static 메서드

```java
public static String deco(String str)
```

특징:

- 객체 생성 없이 호출 가능
- 클래스명으로 바로 접근 가능

```java
DecoUtil.deco("hello");
```

---

###  static 메서드의 제한

 static 메서드는
- static 변수 사용 가능
- static 메서드 호출 가능

 static 메서드는
- 인스턴스 변수 접근 불가
- 인스턴스 메서드 호출 불가

이유는 static 메서드는 특정 인스턴스를 참조하지 않기 때문이다.

---

###  main 메서드가 static인 이유

```java
public static void main(String[] args)
```

- 객체 생성 없이 실행되기 때문이다.
- 프로그램의 시작점이기 때문이다.

---

##  이번 파트에서 얻은 가장 중요한 이해

- 자바 메모리는 **메서드 영역 / 스택 / 힙**으로 나뉜다.
- 지역 변수는 스택에서 관리된다.
- 객체는 힙에서 생성된다.
- static 변수는 메서드 영역에서 클래스 단위로 관리된다.
- static은 인스턴스가 아니라 클래스에 소속된다.
- static 메서드는 인스턴스에 접근할 수 없다.

---

##  한 줄 정리

> **객체는 힙에 생성되고, 실행 흐름은 스택이 관리하며, static은 클래스 단위로 메서드 영역에서 공유된다.**
