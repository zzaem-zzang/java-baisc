# 📘 Java Basic - 객체 지향 프로그래밍

이번 학습에서는 절차 지향 프로그래밍에서 시작해서,  
데이터와 기능이 분리된 구조를 점진적으로 개선하며  
**객체 지향 프로그래밍(OOP)의 핵심 개념**을 이해했다.

특히 음악 플레이어 예제를 통해  
단순히 클래스를 만드는 것이 아니라,  
**관련된 데이터와 기능을 하나로 묶는 방식**이 왜 중요한지 학습했다.

---

## 이번에 학습한 핵심 내용

### 절차 지향 프로그래밍의 특징
처음에는 음악 플레이어를 단순히 변수와 순서 중심으로 구현했다.

- `volume`
- `isOn`

그리고 main 메서드 안에서 순서대로

- 음악 플레이어 켜기
- 볼륨 증가/감소
- 상태 확인
- 음악 플레이어 끄기

를 직접 처리했다.

이 방식은 동작은 단순하지만, 기능이 많아질수록  
코드가 길어지고 중복이 생기며 유지보수가 어려워질 수 있다.

---

### 데이터만 클래스로 묶는 방식 (절차 지향 개선)
다음 단계에서는 `MusicPlayerData` 클래스를 만들어  
음악 플레이어와 관련된 데이터를 하나로 묶었다.

- `volume`
- `isOn`

이렇게 하면 음악 플레이어와 관련된 값들을  
하나의 객체(`data`)로 관리할 수 있어서 이전보다 구조가 좋아진다.

하지만 여전히 한계가 있었다.

- 데이터는 `MusicPlayerData`에 있고
- 기능은 `main` 또는 `static` 메서드에 존재

즉, **데이터와 기능이 여전히 분리되어 있다.**

---

### 메서드 추출로 기능 분리하기
반복되는 코드를 메서드로 추출하면서 구조를 더 개선했다.

예를 들어:

- `on(data)`
- `off(data)`
- `volumeUp(data)`
- `volumeDown(data)`
- `showStatus(data)`

이렇게 기능 단위로 나누면

- 중복 제거
- 재사용성 증가
- 가독성 향상
- 수정 범위 축소

같은 장점이 생긴다.

하지만 이 단계도 여전히  
**데이터와 기능이 서로 다른 곳에 나뉘어 있는 절차 지향 구조**라는 점을 확인했다.

---

### 클래스는 데이터 + 기능을 함께 가질 수 있음
이번 파트에서 중요한 포인트는  
클래스가 단순히 데이터만 담는 공간이 아니라는 점이다.

자바의 클래스는

- 속성(멤버 변수)
- 기능(메서드)

을 함께 가질 수 있다.

예를 들어 `ValueObject` 클래스는

- `int value`
- `void add()`

를 함께 가지고 있어서,  
객체가 자신의 데이터를 스스로 처리하는 구조를 만들 수 있다.

 이번 파트에서 중요한 학습 포인트:  
**“객체는 자신의 데이터와 기능을 함께 가진다.”**

---

### 객체의 메서드 호출과 자기 자신의 데이터 접근
객체의 메서드는 `.`(dot) 연산자로 호출한다.

```java
valueObject.add();
```


이 때 add() 메서드 안에서 실행되는 value++는
외부의 값이 아니라 자기 자신의 객체에 있는 멤버 변수를 의미한다.

즉, 객체는  자신의 메서드로 자신의 데이터를 다룬다는 점을 이해했다.

--- 
### 캡슐화(Encapsulation) 기초 이해

객체 지향에서는 속성과 기능을 하나로 묶고, 외부에는 필요한 기능만 제공하는 방식을 캡슐화라고 한다.

---

## 이번 파트에서 얻은 가장 중요한 이해

- 절차 지향은 실행 순서 중심, 객체 지향은 객체 중심이다
- 절차 지향에서는 데이터와 기능이 분리되어 있다
- 클래스는 데이터뿐 아니라 메서드(기능)도 함께 가질 수 있다
- 객체는 자신의 메서드로 자신의 데이터를 다룬다
- 객체 지향의 핵심은 관련된 데이터와 기능을 하나로 묶는 것이다
- 캡슐화는 변경에 강한 구조를 만든다

--- 

## 한 줄 정리

>  객체 지향 프로그래밍은 데이터와 기능을 하나의 객체로 묶어, 객체 중심으로 설계하는 방식이라는 점을 이해했다.
